# MKR Auth email branding

Reference copies of the branded HTML for Supabase's built-in Auth email
templates. **Not auto-deployed** — Supabase's hosted email templates live
in project config, not in this repo's migrations, and pushing them via
`supabase config push` risks silently overwriting unrelated hosted Auth
settings (see the CLI's own warning: a config.toml generated by
`supabase init` also declares `site_url`, provider toggles, etc. — a push
would apply *all* of it, not just the templates). Paste these manually
instead — zero blast radius, exactly the fields you touch change.

## How to apply

Supabase Dashboard → **Authentication → Email Templates** → pick the
template → paste the **Subject** below into the Subject field → paste the
matching `.html` file's content into the Message body (HTML) field → Save.

| Template (Dashboard name) | Subject to set | File |
|---|---|---|
| Confirm signup | `Confirm your Market Radar (MKR) email` | `confirm-signup.html` |
| Reset Password | `Reset your Market Radar (MKR) password` | `reset-password.html` |
| Change Email Address | `Confirm your new Market Radar (MKR) email` | `change-email.html` |

**Magic Link and Invite user were not touched** — grepped the Flutter
codebase (`signInWithOtp`, `inviteUserByEmail`), neither is used anywhere.
Per the brief's own instruction, a feature isn't enabled just to brand it.

Every template keeps Supabase's own dynamic variable
(`{{ .ConfirmationURL }}`, plus `{{ .NewEmail }}` on the change-email one)
— never a hard-coded URL. Confirmed against Supabase's own docs which
variables belong to which template.

## Sender name / From address

**Not changeable with the current built-in email service, full stop.**
Supabase's built-in Auth mailer always sends as
`Supabase Auth <noreply@mail.app.supabase.io>` — this is a platform-level
constraint of the free/shared mailer, not a template or dashboard setting.
There is no field anywhere in Email Templates or project settings that
renames it.

**To get `Market Radar (MKR) <noreply@yourdomain>` as the sender, Custom
SMTP is required.** Dashboard → **Project Settings → Authentication →
SMTP Settings** (exact path may read "Auth → SMTP Settings" depending on
dashboard version) → enable Custom SMTP, then supply:

- An SMTP provider (Resend, Postmark, SES, SendGrid, etc. — any transactional-email provider)
- A domain you control, with SPF + DKIM (and ideally DMARC) DNS records set up for deliverability — sending "From: yourdomain" without these gets flagged as spam
- Host / port / username / password (or API key) from that provider
- Sender name (`Market Radar` or `Market Radar (MKR)`) and From address (e.g. `noreply@marketradar.app`)

Not configured here — no SMTP credentials exist to configure, and none
should be invented. This is a production-readiness item for whenever you
pick a provider + domain.
